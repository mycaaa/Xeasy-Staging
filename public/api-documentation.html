API Overview

The Laravel API serves the new XEasy backend hosted at expensenew.vnrseeds.co.in. It handles advance requests, payments, employee ledgers, notifications, and reporting.

Base URL

/api — All endpoints are prefixed with this path.

Authentication

Most routes are public (no auth middleware). Some ledger routes use session-based auth.

Standard Response

{success: true/false, message: "...", data: {...}}

Paginated Response

{success: true, data: {items: [...], pagination: {current_page, last_page, per_page, total}}}

Advance Requests

Endpoints for creating, updating, and managing advance requests. Employees can request advances for activities, expenses, or other purposes. Requests go through a multi-level approval workflow.

GET /api/advance List advance requests for a user ▼
Retrieves a list of advance requests created by or associated with a specific user. Results can be filtered by status. Returns full request objects including employee details, activities, and approval summaries.
Parameters
NameTypeRequiredDescription

statusstringOptionalFilter by status: Draft, In Approval, or Approved
Example Request
GET /api/advance?user_id=142&status=Draft
Example Response

Mobile App API Overview

The legacy PHP API serves the Flutter/Android mobile application. Hosted at expense.vnrseeds.co.in. Uses POST form-data with a value field as an action dispatcher.

Base URL

https://expense.vnrseeds.co.in/api/{ComId}/

Authentication

Every request includes: empid, YearId, ComId, tokenid (FCM token)

Method

Most endpoints use POST multipart/form-data with a value field that determines the action

Success Response

{Code: "300", ...data} — Code "300" indicates success

⚠️ Legacy System: This API uses non-standard conventions (GET for mutations, form-data for JSON-like actions). New features should use the Laravel API instead.

System Overview

XEasy is a comprehensive Expense Management System used by VNR Seeds for managing employee expense claims, advance requests, payments, and approvals. The system consists of the following components:

  • Web Application (Laravel) — Admin panel for finance, HR, and management teams to manage claims, approvals, reports, and system configuration
  • Mobile App (Flutter/Android) — Used by field employees to submit expense claims, odometer readings, daily allowance, and advance requests on the go
  • Legacy PHP API — Backend serving the mobile app with claim upload, approval, and data retrieval functionality
  • New Laravel API — Modern backend for advance requests, payments, employee ledger, notifications, and new features being developed
Domains:
• Web Admin: expensenew.vnrseeds.co.in (Laravel)
• Mobile API: expense.vnrseeds.co.in (Legacy PHP)
• Central Service: central.vnrin.in (Notifications)

User Roles

1. Employee / Claimant

Field employees who submit expense claims, odometer readings, DA claims, and advance requests. They use the mobile app primarily.

  • Upload bills and receipts via mobile app camera
  • Record daily odometer readings (opening/closing)
  • Submit Daily Allowance claims
  • Create advance requests for upcoming expenses
  • Confirm verified claims (Claimant Okay)
  • Submit monthly claims for approval

2. Approver / Reporting Manager

Supervises a team of employees and approves their expense claims and advance requests.

  • View team's pending claims by month
  • Approve/reject individual claims with amount adjustments
  • Submit approved claims to finance
  • Approve/reject advance requests
  • Approve odometer backdate requests

3. Verifier

Data entry team that verifies claim details and fills head-wise amounts before claims go for approval.

  • Review uploaded bills and receipts
  • Fill verified amounts for each expense head
  • Flag discrepancies or issues
  • Verify running KM claims

4. Finance

Final approval authority for payments. Processes claims through to payment and handles ERP integration.

  • Final approval of expense claims
  • Process advance request payments
  • Release payments to bank
  • Confirm bank processing
  • Export to Focus ERP
  • Manage employee ledger balances
  • Handle payment discrepancies and settlements

5. Super Admin / Admin

Full system access with configuration and management capabilities.

  • Employee management (create, edit, deactivate)
  • Open/close months for submission
  • Return claims to employees
  • Backend submission for deactivated employees
  • Configure claim types, rates, and rules
  • View all reports and dashboards
  • Manage email templates and reminders
  • Handle duplicate expense cleanup

Expense Claim Lifecycle

Every expense claim goes through the following stages from creation to payment:

  1. Bill Upload (Employee) — Employee takes a photo of the bill or uploads a PDF via the mobile app. The OCR system automatically extracts the date and amount.
  2. Fill Details (Employee) — Employee fills in claim details: amount, date, claim type, and any remarks. Head-wise breakdown if applicable.
  3. Month Submission (Employee) — At the end of the month, employee submits all claims for that month. This locks the month — no more claims can be added.
  4. Verification (Verifier) — Data entry team reviews each claim, checks bills, and fills the verified amounts for each expense head.
  5. Claimant Okay (Employee) — Employee reviews the verified amounts and confirms they're correct, or disputes if amounts are wrong.
  6. Reporting Approval (Approver) — Reporting Manager reviews claims, adjusts amounts if needed, and approves. Then submits to finance.
  7. Finance Processing (Finance) — Finance team does final review, approves the final amount, and processes payment.
  8. Payment Release (Finance) — Payment is released via Focus ERP integration. Bank confirms processing.
Stage Abbreviations in Database:
Filled → Verified → Claimant OK → Reporting Approved → Finance Approved → Payment Released → Confirmed

Advance Request Lifecycle

Advance requests allow employees to receive money in advance for planned activities or expenses:

  1. Create Request (Employee) — Employee creates an advance request specifying the type (Activity/Expense/Other), adds team members and activities with estimated amounts.
  2. Submit for Approval — Request changes from "Draft" to "In Approval" and notifications are sent to approvers.
  3. Multi-level Approval (Approvers) — One or more approvers review and approve/reject the request. Each level can adjust amounts.
  4. Finance Approval — Finance team gives final approval on the amounts.
  5. Payment Release — Finance releases the payment to the employee's bank account.
  6. Bank Confirmation — Payment is confirmed as processed by the bank.
  7. Focus ERP Export — Payment data is exported to Focus accounting system.
  8. Settlement — The advance is settled against future expense claims. Any unused amount is tracked in the employee ledger.
⚠️ Important: Advance payments create a debit in the employee's ledger. They must be settled against expense claims or returned. Outstanding advances are tracked until fully settled.

Odometer Flow

The odometer system tracks daily vehicle usage for travel claim calculation:

  1. Select Date & Vehicle — Employee selects the date and vehicle type (2-Wheeler or 4-Wheeler). Different rates apply for each.
  2. Opening Reading — Employee takes a photo of the vehicle odometer at the start of the day and enters the reading.
  3. Closing Reading — At end of day, employee takes another photo and enters the closing reading. Must be greater than opening.
  4. Auto-Calculation — System calculates total KM (closing - opening) and applies the rate based on vehicle type and employee grade.
  5. Draft Claim Created — A travel claim is automatically created in draft with the calculated amount.
Vehicle Types:
• 2 = Two-Wheeler (motorcycle/scooter) — lower per-KM rate
• 4 = Four-Wheeler (car) — higher per-KM rate

Backdate: If an employee misses a day, they can submit a backdate request which requires reporting manager approval.

Month Submission Process

The monthly submission process is how employees finalize their claims for a given month:

  1. Fill Claims — Employee fills all claims for the month (bills, DA, odometer) throughout the month.
  2. Review in Open Month — Before submitting, employee reviews all claims in the "Open Month" view to ensure completeness.
  3. Submit Month — Employee clicks "Submit" which closes the month. No more claims can be added after this.
  4. Processing Pipeline — Claims move through: Verify → Claimant OK → Reporting Approval → Finance
  5. Payment — Once all stages are complete, payment is processed and released.
Prerequisites for Submission:
• SubPermission (Allow Submit) must be enabled by admin
• All required odometer entries must be complete
• Month must be "Open" (admin controls which months are open)
⚠️ Note: Once submitted, a month can only be reopened by an Admin using the "Return Claim" feature. Employees cannot undo submission themselves.

Key Business Rules

  • Only one DA per day — The system prevents submitting more than one Daily Allowance claim for the same date.
  • Odometer closing > opening — The closing odometer reading must always be greater than the opening reading for that day.
  • No editing after submission — Once claims are submitted for a month, they cannot be modified by the employee.
  • Month can be reopened by Admin — Using the "Return Claim" feature, admins can send a submitted month back to the employee.
  • Backend Submission — For deactivated employees, admins can submit claims on their behalf using the backend submission feature.
  • Running KM tracking — The system tracks cumulative KM per employee per month, separately for 2W and 4W vehicles.
  • Sub-Permission required — The "Allow Submit" permission must be enabled before an employee can submit their monthly claims.
  • Advance settlement — Advance payments are tracked as debits in the employee ledger and must be settled against future expense claims.
  • Multi-level approval — Advance requests can go through multiple approval levels based on amount and organizational hierarchy.
  • Soft delete only — Draft advance requests are soft-deleted (marked as deleted but retained in database). Submitted requests cannot be deleted.
  • Year-prefixed tables — Expense data tables are prefixed with the year ID: y{YearId}_expenseclaims, y{YearId}_g1_expensefilldata, etc.

Financial Year

The system operates on Indian financial years (April to March):

  • YearId = 7 is the current active year (2024-2025, April 2024 to March 2025)
  • Year list is fetched dynamically from the API at login time
  • Only the "Active" year allows new claim submissions
  • Previous years remain accessible in read-only mode for reporting
⚠️ Database Architecture: All expense data tables are year-prefixed. For example:
• y7_expenseclaims — Main claims table for Year 7
• y7_g1_expensefilldata — Head-wise expense amounts for Year 7
• y7_expense_monthfinal — Monthly submission records for Year 7

This means queries must always include the correct year prefix based on the selected financial year.

Web Admin Features

Employee Page

Manage individual employee claims and permissions:

  • View Claims by Month — See all claims for an employee in a specific month
  • Allow Submit — Enable/disable the employee's ability to submit monthly claims
  • Return Claims — Send submitted claims back to the employee for corrections
  • Backend Submission — Submit claims on behalf of deactivated employees

Open Month

Control which months are open for claim entries. Admin can open or close months for all employees. Closed months prevent new claim submissions.

Claim Rating

Rate claim quality per employee based on configurable rules. Helps identify employees with frequent issues or excellent compliance.

Reports

  • Running KM Report — Track total kilometers claimed per employee per month
  • Claim Stage Dashboard — Overview of all claims and their current processing stage
  • Ledger Summary — Employee-wise advance balance and transaction history
  • Payment Reports — Track all payments, batches, and bank confirmations
  • Department-wise Reports — Aggregate expenses by department
  • Delay Tracking — Identify bottlenecks in claim processing

Duplicate Expense

Find and delete duplicate expense fill data records. Used for data maintenance when system errors create duplicate entries in the g1_expensefilldata table.

Email Templates

Manage notification email templates for various events (submission reminder, approval notification, payment confirmation, etc.).

Submission Reminder

Send reminder notifications to employees who haven't submitted their claims for the current month. Can be sent individually or in bulk.
