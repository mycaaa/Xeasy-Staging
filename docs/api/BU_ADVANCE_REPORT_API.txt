================================================================================
BU LEVEL ADVANCE REPORT API DOCUMENTATION
================================================================================

OVERVIEW:
This API provides Business Unit (BU) level advance payment reports.
BU Level employees are identified by: BUId > 0, ZoneId = 0, RegionId = 0, TerrId = 0

BASE URL: /api/advance/bu

================================================================================
ENDPOINTS
================================================================================

1. GET BUSINESS UNITS LIST
   Endpoint: GET /api/advance/bu/business-units
   
   Parameters:
   - search (optional): Search term for BU name, code, or numeric code
   - limit (optional): Number of records to return (default: 10)
   
   Example:
   GET /api/advance/bu/business-units?search=sales&limit=10

================================================================================
BU LEVEL IDENTIFICATION LOGIC
================================================================================

BU Level employees are identified by the following criteria in hrm_employee_general:
- BUId > 0 (assigned to a Business Unit)
- ZoneId = 0 (not assigned to a Zone)
- RegionId = 0 (not assigned to a Region)
- TerrId = 0 (not assigned to a Territory)

This ensures only employees at the Business Unit level are included in reports.

================================================================================
DATABASE TABLES USED
================================================================================

1. hrm_employee_general - Employee hierarchy assignments
2. hrm_employee - Employee basic information
3. advance_requests - Advance request master data
4. advance_request_employees - Employee-request mapping
5. advance_request_activities - Activity details and payment info
6. advance_activity_approvals - Approval workflow details
7. core_business_unit - Business unit master data
8. core_departments - Department master data
9. core_designation - Designation master data
10. claimtype - Activity name master data
11. adv_activity_types - Activity type master data
12. core_crops - Crop master data

================================================================================
IMPORTANT NOTES
================================================================================

1. Only PAID advances are included in the consolidated report
2. Payment status must be 'Paid' and payment_date must not be null
3. Hierarchy information is included for each employee
4. Approval details show the complete approval workflow
5. Finance details show finance approval information
6. Payment details show actual payment information
7. Totals are calculated at multiple levels:
   - Grand Total (across all activities)
   - Activity Total (per activity)
   - Month Total (per month within activity)
   - Submitted By Total (per submitter)
   - Employee Total (per employee)

================================================================================
COMPARISON WITH HOD CONTROLLER
================================================================================

HOD Controller:
- Uses hrm_employee_reporting.HodId to find team members
- Supports all hierarchy levels (BU, Zone, Region, Territory)
- Supports hierarchy filtering

BU Controller:
- Uses hrm_employee_general with BU level logic
- Only shows BU level employees (BUId > 0, others = 0)
- Focused specifically on Business Unit level reporting
- Simpler, dedicated to BU level only
