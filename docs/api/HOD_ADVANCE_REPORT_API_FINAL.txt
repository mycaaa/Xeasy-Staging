1. GET CONSOLIDATED REPORT
================================================================================

Endpoint: GET /api/advance/hod/consolidated-report

Description: 
Get consolidated advance payment report. Shows only PAID advances grouped by 
Activity → Month → Submitted By → Employee → Requests. Can filter by HOD or 
hierarchy levels (BU, Zone, Region, Territory).

Query Parameters:
  - hod_id (optional)      : HOD Employee ID (for team-based filtering)
  - employee_id (optional) : Filter by specific employee
  - year_id (optional)     : Filter by year ID
  - month (optional)       : Filter by month (1-12)
  - bu_id (optional)       : Filter by Business Unit ID (BU level: BU>0, others=0)
  - zone_id (optional)     : Filter by Zone ID (Zone level: BU>0, Zone>0, others=0)
  - region_id (optional)   : Filter by Region ID (Region level: BU>0, Zone>0, Region>0, Terr=0)
  - terr_id (optional)     : Filter by Territory ID (Territory level: all>0)

Note: At least one filter is required (hod_id, bu_id, zone_id, region_id, terr_id, or employee_id)

Hierarchy Level Logic:
- BU Level: BUId > 0, ZoneId = 0, RegionId = 0, TerrId = 0
- Zone Level: BUId > 0, ZoneId > 0, RegionId = 0, TerrId = 0
- Region Level: BUId > 0, ZoneId > 0, RegionId > 0, TerrId = 0
- Territory Level: BUId > 0, ZoneId > 0, RegionId > 0, TerrId > 0

Example Request:
# By HOD
GET /api/advance/hod/consolidated-report?hod_id=51&year_id=2026&month=2

# By Business Unit (BU level employees only)
GET /api/advance/hod/consolidated-report?bu_id=5&year_id=2026&month=2

# By Zone (Zone level employees only)
GET /api/advance/hod/consolidated-report?bu_id=5&zone_id=10&year_id=2026&month=2

# By Region (Region level employees only)
GET /api/advance/hod/consolidated-report?bu_id=5&zone_id=10&region_id=25&year_id=2026&month=2

# By Territory (Territory level employees only)
GET /api/advance/hod/consolidated-report?bu_id=5&zone_id=10&region_id=25&terr_id=100&year_id=2026&month=2

2. GET TEAM MEMBERS LIST
================================================================================

Endpoint: GET /api/advance/hod/team

Description: 
Get list of employees who have taken advances. Can filter by HOD or hierarchy 
levels. Only employees with advance requests are shown.

Query Parameters:
  - hod_id (optional)    : HOD Employee ID
  - bu_id (optional)     : Business Unit ID (BU level filtering)
  - zone_id (optional)   : Zone ID (Zone level filtering)
  - region_id (optional) : Region ID (Region level filtering)
  - terr_id (optional)   : Territory ID (Territory level filtering)

Note: At least one filter is required

GET /api/advance/hod/team?hod_id=51

# By Business Unit (BU level employees)
GET /api/advance/hod/team?bu_id=5

# By Zone (Zone level employees)

================================================================================
DATA FLOW & HIERARCHY
================================================================================

Hierarchy Levels (Top to Bottom):
1. Business Unit (BUId)     → Highest level
2. Zone (ZoneId)            → Second level
3. Region (RegionId)        → Third level
4. Territory (TerrId)       → Lowest level (City/Village)

Report Grouping Structure:
Activity Name
  └── Month
      └── Submitted By (Person who submitted the request)
          └── Employee (Person for whom advance was requested)
              └── Advance Requests
                  └── Activities
                      ├── Approvals (All approval levels)
                      ├── Finance (Finance approval details)
                      └── Payment (Payment details)

================================================================================
DATABASE TABLES USED
================================================================================

Main Tables:
- advance_requests              : Advance request header
- advance_request_employees     : Employees in the request
- advance_request_activities    : Activities in the request
- advance_activity_approvals    : Approval details

HRIMS Tables (hrims connection):
- hrm_employee                  : Employee master
- hrm_employee_general          : Employee general info with hierarchy
- hrm_employee_reporting        : Reporting structure (HOD mapping)
- core_departments              : Department master
- core_designation              : Designation master
- core_business_unit            : Business Unit master
- core_zones                    : Zone master
- core_regions                  : Region master
- core_region_territory         : Region to Territory mapping (used for territories)
- core_crops                    : Crop master

Hierarchy Mapping Tables:
- core_bu_zone_mapping          : Business Unit to Zone mapping
- core_zone_region_mapping      : Zone to Region mapping (if exists)
- core_region_territory         : Region to Territory mapping

Note: Territory information is fetched from core_region_territory table 
instead of core_city_village_by_state. The TerrId in hrm_employee_general 
maps to territory_id in core_region_territory table.

Other Tables:
- claimtype                     : Activity name master
- adv_activity_types            : Activity type master

================================================================================
IMPORTANT NOTES
================================================================================

1. Only PAID advances are shown in the consolidated report
2. Hierarchy filters (bu_id, zone_id, region_id, terr_id) are applied at the 
   team member level first, then advance data is filtered
3. The getTeamMembers() method handles all hierarchy filtering internally by 
   joining with hrm_employee_general table
4. All amounts are in float format
5. Dates are in 'Y-m-d H:i:s' format
6. Employee hierarchy is fetched from hrm_employee_general table
7. Team members are identified using hrm_employee_reporting.HodId
8. Month filter uses advance_requests.month column (1-12)
9. Year filter uses advance_requests.year_id column
10. All hierarchy APIs return only active records (is_active = '1')
11. Hierarchy mapping shows only team members of the specified HOD
12. Territory information uses core_region_territory table (not core_city_village_by_state)
13. Cascading filters work at team member level: BU → Zone → Region → Territory

================================================================================
FRONTEND IMPLEMENTATION GUIDE
================================================================================

Step 1: Load Filter Options (with Multi-Level Cascading & Search)
- Call /business-units (loads first 10 by default)
- When user selects a Business Unit:
  - Call /zones?business_unit_id=5 (loads zones for that BU)
  - Call /regions?business_unit_id=5 (loads regions for that BU - cascades through zones)
  - Call /territories?business_unit_id=5 (loads territories for that BU - cascades through zones & regions)
- When user selects a Zone:
  - Call /regions?zone_id=10 (loads regions for that zone)
  - Call /territories?zone_id=10 (loads territories for that zone - cascades through regions)
- When user selects a Region:
  - Call /territories?region_id=25 (loads territories for that region)
- Implement search as user types: /business-units?search=seeds
- Call /hierarchy-mapping to show team structure
- Call /team to get employee list

Multi-Level Cascading Filter Flow:
- Business Unit → Zones, Regions, Territories
- Zone → Regions, Territories
- Region → Territories

This allows users to select any level and automatically filter all lower levels!

Step 2: Apply Filters
- User selects HOD, Year, Month, and optional hierarchy filters
- Call /consolidated-report with selected parameters

Step 3: Display Report
- Group data by Activity → Month → Submitted By → Employee
- Show totals at each level (grand_total, month_total, submitted_by_total, employee_total)
- Display approval flow, finance details, and payment information
- Show employee hierarchy information

Step 4: Export/Print
- Use the structured JSON data to generate Excel/PDF reports
- Include all hierarchy levels and totals
